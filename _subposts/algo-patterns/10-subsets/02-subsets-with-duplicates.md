## Условие задачи

Дан набор чисел, который может содержать дубликаты. Найдите все его различные подмножества.

**Пример 1:**

```text
Вход: [1, 3, 3]
Выход: [], [1], [3], [1, 3], [3, 3], [1, 3, 3]
```

**Пример 2:**

```text
Вход: [1, 5, 3, 3]
Выход: [], [1], [5], [3], [1, 5], [1, 3], [5, 3], [1, 5, 3],
       [3, 3], [1, 3, 3], [3, 3, 5], [1, 5, 3, 3]
```

## Решение

Задача следует паттерну «Подмножества». Можно применить тот же подход BFS, но теперь нужно обработать повторяющиеся числа. Если добавлять каждое число ко всем существующим подмножествам, в результате появятся дубликаты.

Добавим два правила:

1. Сортируем числа, чтобы одинаковые элементы оказались рядом.
2. Если текущее число совпадает с предыдущим, добавляем его только к подмножествам, созданным на предыдущем шаге.

Разберём набор `[1, 5, 3, 3]`. После сортировки получим `[1, 3, 3, 5]`:

1. Начинаем с `[[]]`.
2. После добавления `1` получаем `[[], [1]]`.
3. После первой `3` получаем `[[], [1], [3], [1, 3]]`.
4. Если добавить вторую `3` ко всем подмножествам, получится `[[], [1], [3], [1, 3], [3], [1, 3], [3, 3], [1, 3, 3]]`. Подмножества `[3]` и `[1, 3]` повторяются.
5. Вместо этого добавляем вторую `3` только к `[3]` и `[1, 3]`, созданным на предыдущем шаге. Получаем `[[], [1], [3], [1, 3], [3, 3], [1, 3, 3]]`.
6. Число `5` отличается от предыдущего, поэтому добавляем его ко всем подмножествам. Итог: `[[], [1], [3], [1, 3], [3, 3], [1, 3, 3], [5], [1, 5], [3, 5], [1, 3, 5], [3, 3, 5], [1, 3, 3, 5]]`.

[![Построение подмножеств с повторяющейся тройкой без дубликатов в результате](/assets/img/posts/2027-01-01-algo-patterns-subsets/subsets-with-duplicates-steps.svg)](/assets/img/posts/2027-01-01-algo-patterns-subsets/subsets-with-duplicates-steps.svg)

Переменные `startIndex` и `endIndex` задают диапазон подмножеств для текущего шага. Для повторяющегося числа начало берём сразу после старого `endIndex`. Затем обновляем `endIndex`, фиксируя конец списка до добавления новых подмножеств.

## Код

Код сортирует входной срез `nums` на месте.

{% raw %}
```go
package main

import (
	"fmt"
	"sort"
)

func findSubsets(nums []int) [][]int {
	sort.Ints(nums)
	subsets := [][]int{{}}
	startIndex, endIndex := 0, 0
	for i, currentNumber := range nums {
		startIndex = 0
		if i > 0 && currentNumber == nums[i-1] {
			startIndex = endIndex + 1
		}
		endIndex = len(subsets) - 1
		for j := startIndex; j <= endIndex; j++ {
			set := make([]int, len(subsets[j])+1)
			copy(set, subsets[j])
			set[len(subsets[j])] = currentNumber
			subsets = append(subsets, set)
		}
	}
	return subsets
}
func main() {
	fmt.Println("Подмножества:", findSubsets([]int{1, 3, 3}))
	fmt.Println("Подмножества:", findSubsets([]int{1, 5, 3, 3}))
}
```
{% endraw %}

**Вывод:**

```text
Подмножества: [[] [1] [3] [1 3] [3 3] [1 3 3]]
Подмножества: [[] [1] [3] [1 3] [3 3] [1 3 3] [5] [1 5] [3 5] [1 3 5] [3 3 5] [1 3 3 5]]
```

## Временная сложность

Если повторов нет, количество подмножеств удваивается на каждом шаге. В оригинале приведена оценка $$O(2^N)$$ по количеству подмножеств, где $$N$$ — число входных элементов.

С учётом копирования элементов показанный Go-код требует $$O(N \cdot 2^N)$$ времени в худшем случае. Сортировка занимает $$O(N \log N)$$ и не меняет итоговую оценку.

## Пространственная сложность

Все дополнительные данные хранятся в результате. Оригинал оценивает число подмножеств как $$O(2^N)$$; хранение их элементов в Go-срезах требует $$O(N \cdot 2^N)$$ памяти в худшем случае.
