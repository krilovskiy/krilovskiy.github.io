# Дополнение существующей главы Algo Patterns

Найди действительно отсутствующие задачи локального оригинала и добавь их в существующую главу, не раздувая основную статью и не меняя опубликованные URL.

## Объект и граница

- Работай только в активном git checkout, определённом через `git rev-parse --show-toplevel`; не используй абсолютный путь к другому checkout как цель.
- Локальный источник Educative по умолчанию: `/Users/user/projects/blog/Educative.io - Grokking the Coding Interview - Patterns for Coding Questions` (только чтение). Если он недоступен, останови только проверку покрытия и назови недостающий путь.
- `_data/notes/algo.md` — набор отправных ссылок, а не доказательство соответствия задач.

Этот скилл предполагает изменение файлов. Если пользователь просит только найти пробелы или проверить главу, используй `algo-patterns-review`. Не переписывай всю главу и не исправляй несвязанные проблемы без отдельного запроса.

## Найди реальный пробел

1. Прочитай `AGENTS.md`, основную статью, все субпосты с тем же `pattern`, `_includes/algo-task-nav.html` и defaults коллекции `subposts` в `_config.yml`.
2. Инвентаризируй соответствующую папку Educative, включая challenge и solution review.
3. Сопоставь каждую содержательную исходную задачу с основной статьёй, существующим субпостом, точным дублем или отсутствием. Сравнивай условие, примеры и алгоритм, а не только заголовок.
4. Добавляй только подтверждённые пропуски. Внешняя ссылка из `Похожие задания` не считается публикацией исходной задачи.

Перед исполнением или делегированием прочитай [golden example](references/golden-example.md). Он показывает корректный handoff и добавление одного подтверждённого пробела, но не задаёт текущие идентификаторы и не является доказательством покрытия.

## Добавь задачу

- Помести новый файл в существующий каталог `_subposts/algo-patterns/NN-pattern-name/`.
- Числовой префикс отражает исходный порядок. При вставке между задачами можно менять имена файлов только когда это не меняет опубликованные `permalink`; существующие публичные URL сохраняй.
- Используй только необходимые поля `title`, `description`, `pattern`, `permalink` и верхний/нижний include `algo-task-nav.html`. Не добавляй ручные `order`, `total_tasks`, `parent_*`, `previous_*` или `next_*`.
- Добавь ссылку в `## Задачи главы` основной статьи в том же порядке, не копируя туда полное решение.
- Переводи условие, примеры, алгоритм и сложности близко к оригиналу; не добавляй чужих альтернатив и обобщений.
- Go-код должен быть самостоятельной программой `package main`, согласованной с терминологией и моделями данных главы.
- Добавляй только относящиеся к новой задаче уникальные локальные схемы. Не меняй инфраструктуру коллекции или layout, если текущий механизм уже решает задачу.
- Не меняй `Похожие задания`, если пользователь этого не просил и там нет фактической ошибки. При исправлении включай только подтверждённые соответствия, без фиксированного количества.

## Проверка

1. Повтори карту покрытия и докажи, что новый субпост закрывает заявленный пробел, а не дублирует другую страницу источника.
2. Для каждого нового или изменённого Go-блока отдельно выполни `gofmt`, `go run`, основной пример и релевантные граничные случаи.
3. Проверь `ruby -v`, `bundle -v`, `bundle check`; используй уже установленный совместимый Ruby и не меняй глобальное окружение без разрешения.
4. Собери Jekyll с `--future` в новый destination из `mktemp -d`. Запусти HTML-Proofer для него с опциями внутренних ссылок из CI/Makefile и отдели существующие предупреждения от новых.
5. Проверь URL, номер, соседние ссылки и переходы на границах. Убедись, что субпост не попал в обычную ленту, feed, архив или поиск.
6. Визуально проверь широкую и узкую ширину, если менялись изображения, формулы, навигация или layout.

Если часть проверок недоступна, сообщи точную ошибку и не называй её пройденной. В финале перечисли добавленные задачи, изменённые файлы, новое покрытие и результаты проверок.
